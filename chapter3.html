2  大语言模型基础

Note上一章回顾

第 2 章我们回溯了智能体的发展历史——从 ELIZA 的规则匹配到 AlphaGo 的强化学习，最终汇聚于大语言模型驱动的现代 Agent。在开始为 Agent 添加工具和推理能力之前，我们需要先掌握驱动 Agent “大脑”的核心技术：大语言模型。

本章介绍构建 LLM Agent 必需的 LLM 基础知识。我们将跳过模型训练的数学推导，聚焦于使用层面：如何调用 LLM、如何设计 Prompt、如何理解分词机制。对于 Transformer 的内部结构，我们只讲清楚”注意力机制在做什么”——足够你在调试 Agent 时定位问题即可。

2.1 语言模型的核心思想

语言模型（Language Model, LM）的根本任务是计算一个词序列（句子）出现的概率。一个好的语言模型能够告诉我们什么样的句子是”通顺的、自然的”。

2.1.1 从 N-gram 开始

在深度学习兴起之前，统计方法是主流。对于由词 \(w_1, w_2, \ldots, w_m\) 构成的句子 \(S\)，其概率可以表示为：

\[ P(S) = P(w_1) \cdot P(w_2 \mid w_1) \cdot P(w_3 \mid w_1, w_2) \cdots P(w_m \mid w_1, \ldots, w_{m-1}) \]

这个公式称为链式法则。但直接计算条件概率 \(P(w_m \mid w_1, \ldots, w_{m-1})\) 几乎不可能——词序列 \(w_1, \ldots, w_{m-1}\) 本身可能从未在训练数据中出现过。

为此，研究者引入了马尔可夫假设：一个词的出现概率只与它前面有限的 \(n-1\) 个词有关。基于这个假设建立的模型称为 N-gram 模型。

  • Bigram（N=2）：\(P(w_i \mid w_1, \ldots, w_{i-1}) \approx P(w_i \mid w_{i-1})\)
  • Trigram（N=3）：\(P(w_i \mid w_1, \ldots, w_{i-1}) \approx P(w_i \mid w_{i-2}, w_{i-1})\)

概率通过最大似然估计计算：用词对出现的次数除以单个词出现的总次数。

# Bigram 语言模型示例
corpus = "simple agent learns simple agent works"
tokens = corpus.split()
total_tokens = len(tokens)

# 第一步：计算 P(simple)
count_simple = tokens.count("simple")
p_simple = count_simple / total_tokens
print(f"P(simple) = {count_simple}/{total_tokens} = {p_simple:.3f}")

# 第二步：构造 bigrams 并计算 P(agent | simple)
bigrams = list(zip(tokens[:-1], tokens[1:]))
count_simple_agent = bigrams.count(("simple", "agent"))
p_agent_given_simple = count_simple_agent / count_simple
print(f"P(agent|simple) = {count_simple_agent}/{count_simple} = {p_agent_given_simple:.3f}")

# 第三步：计算 P(learns | agent)
count_agent = tokens.count("agent")
count_agent_learns = bigrams.count(("agent", "learns"))
p_learns_given_agent = count_agent_learns / count_agent
print(f"P(learns|agent) = {count_agent_learns}/{count_agent} = {p_learns_given_agent:.3f}")

# 句子概率连乘
p_sentence = p_simple * p_agent_given_simple * p_learns_given_agent
print(f"\nP('simple agent learns') ≈ {p_sentence:.3f}")

N-gram 模型有两个致命缺陷：数据稀疏性（未见过的词序列概率为 0）和泛化能力差（无法理解”agent”和”robot”的语义相似性）。这些缺陷催生了神经网络语言模型。

2.1.2 词嵌入：让机器理解语义

神经网络语言模型的核心创新是用连续的向量来表示词——即词嵌入（Word Embedding）。语义相近的词，其向量在空间中位置相近。

我们可以用余弦相似度衡量两个词向量的语义距离：

import math

def cosine_similarity(vec1, vec2):
    dot_product = sum(a * b for a, b in zip(vec1, vec2))
    norm_product = math.sqrt(sum(a*a for a in vec1)) * math.sqrt(sum(b*b for b in vec2))
    return dot_product / norm_product

# 二维词向量（简化示例）
embeddings = {
    "king":  [0.9, 0.8],
    "queen": [0.9, 0.2],
    "man":   [0.7, 0.9],
    "woman": [0.7, 0.3],
}

# 经典类比：king - man + woman ≈ queen
result_vec = [
    embeddings["king"][0] - embeddings["man"][0] + embeddings["woman"][0],
    embeddings["king"][1] - embeddings["man"][1] + embeddings["woman"][1],
]
sim = cosine_similarity(result_vec, embeddings["queen"])
print(f"king - man + woman 与 queen 的相似度: {sim:.4f}")

2.2 Transformer：现代 LLM 的基石

2017 年，谷歌团队提出了 Transformer 架构。它的核心创新是完全舍弃循环结构，仅依赖注意力机制（Attention）来建模序列内部的依赖关系。

2.2.1 自注意力：让每个词”看见”所有其他词

在阅读句子 “The agent learns because it is intelligent” 时，为了理解 “it” 的指代，我们的大脑会不自觉地将更多注意力放在前面的 “agent” 上。自注意力（Self-Attention） 正是对这一过程的数学建模。

自注意力为每个词引入三个可学习的角色：

  • 查询（Query, Q）：当前词元正在主动”查询”其他词元。
  • 键（Key, K）：词元被查询时的”标签”。
  • 值（Value, V）：词元本身携带的”内容”。

计算过程可概括为：用 Q 和所有 K 做点积得到相关性分数 → 缩放 + Softmax 得到注意力权重 → 用权重加权求和 V，得到融合了全局上下文的新表示。

\[ \mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{Q K^{T}}{\sqrt{d_k}}\right) V \]

多头注意力则更进一步：将 Q、K、V 切分成多份（“头”），每一份独立计算注意力，最后拼接结果。这就像让多个”专家”从不同角度去审视句子，每个专家关注不同类型的关联（指代关系、时态关系、修饰关系等）。

2.2.2 Decoder-Only 架构

Transformer 原始论文采用编码器-解码器架构，但 OpenAI 在开发 GPT 时做了一个大胆的简化：完全抛弃编码器，只保留解码器。这就是 Decoder-Only 架构。

其工作模式称为自回归（Autoregressive）：

  1. 给模型起始文本（如 “Simple Agent is”）
  2. 模型预测下一个词（如 “a”）
  3. 将新词拼接到输入末尾（“Simple Agent is a”）
  4. 重复直到生成完整句子

这种”预测下一个词”的简单范式，非常适合在海量文本上预训练，天然适合所有生成式任务。今天的 GPT-4、Llama 等模型都基于这一架构。

Tip你需要理解到什么程度？

作为 Agent 开发者，你不需要从零实现 Transformer。但理解自注意力的直觉——“让模型在生成每个词时能够参考上下文中所有其他词”——对于调试 Agent 行为（例如理解为什么模型会”忘记”早期的指令）非常有帮助。

2.3 与大语言模型交互

2.3.1 模型采样参数

在调用 LLM 时，你经常会看到以下可配置参数。它们本质上是调整模型对”概率分布”的采样策略：

Temperature（温度）

\[ p_i^{(T)} = \frac{e^{z_i / T}}{\sum_{j} e^{z_j / T}} \]

温度范围 效果 适用场景
低（0 ~ 0.3） 输出确定、保守 事实问答、代码生成
中（0.3 ~ 0.7） 平衡、自然 日常对话、文案撰写
高（0.7 ~ 2.0） 创新、发散 创意写作、头脑风暴

Top-k 采样：只从概率最高的 k 个 token 中采样，截断低概率”噪声”。

Top-p 采样：从高到低累积概率，只保留累积概率达到 p 的最小 token 集合。相比 Top-k，它能动态适应不同分布的”长尾”特性。

当同时设置这些参数时，优先级为：温度调整 → Top-k → Top-p。

2.3.2 提示工程基础

提示工程（Prompt Engineering）是研究如何设计精准的提示来引导模型产生期望输出的学问。以下是几个核心技巧：

1. 零样本 / 少样本提示

# 零样本：不给示例，直接下指令
请将下面的英文翻译成中文：How are you?

# 少样本：给几个示例后让模型推断模式
英文: Hello → 中文: 你好
英文: Goodbye → 中文: 再见
英文: How are you? → 中文:

2. 角色扮演

你现在是一位资深的 Python 编程专家。请向初学者解释 GIL（全局解释器锁）。

3. 思维链（Chain-of-Thought）

面对需要多步推理的复杂问题，引导模型”逐步思考”：

一个篮球队在 80 场比赛中赢了 60%。接下来的赛季他们打了 15
场赢了 12 场。两个赛季的总胜率是多少？请逐步思考并解答。
Important

Agent Prompt ≠ 普通提示词。在第 4、5 章我们将看到，Agent 的 System Prompt 实际上是一份通信协议——它定义了 Thought/Action 格式、工具调用语法和终止条件。这是 Agent 与普通 ChatBot 的第一道分水岭。

2.4 文本分词

计算机只能处理数字，因此文本必须先转换为数值形式。这个过程称为分词（Tokenization），其输出单元称为 Token。

2.4.1 为什么需要子词分词

早期分词方式各有缺陷： - 按词分词：词表膨胀，无法处理新词（OOV 问题）。 - 按字符分词：语义弱，模型需额外学习组合规则。

现代 LLM 普遍采用子词分词（Subword Tokenization）：常见词保留为完整 token，罕见词拆分为多个有意义的子词片段。

2.4.2 字节对编码（BPE）

BPE（Byte-Pair Encoding） 是最主流的子词分词算法，GPT 系列模型即采用它。其核心是一个”贪心”合并过程：

  1. 将词表初始化为所有基本字符
  2. 统计所有相邻 token 对的频率，合并最高频的一对
  3. 重复直到词表达到预设大小
from collections import Counter

def get_stats(vocab):
    """统计所有相邻 token 对的频率"""
    pairs = Counter()
    for word, freq in vocab.items():
        symbols = word.split()
        for i in range(len(symbols) - 1):
            pairs[(symbols[i], symbols[i + 1])] += freq
    return pairs

def merge_vocab(pair, vocab):
    """合并指定 token 对"""
    bigram = " ".join(pair)
    replacement = "".join(pair)
    new_vocab = {}
    for word, freq in vocab.items():
        new_word = word.replace(bigram, replacement)
        new_vocab[new_word] = freq
    return new_vocab

# 迷你语料库（每个字符用空格分隔，</w> 表示词尾）
vocab = {
    "h u g </w>": 1,
    "p u g </w>": 1,
    "p u n </w>": 1,
    "b u n </w>": 1,
}

print("初始词表:", list(vocab.keys()))

num_merges = 4
for i in range(num_merges):
    pairs = get_stats(vocab)
    if not pairs:
        break
    best_pair = pairs.most_common(1)[0][0]
    print(f"合并: {best_pair}")
    vocab = merge_vocab(best_pair, vocab)

print("最终词表:", list(vocab.keys()))

对于一个未见过的词 “bug”，分词器会先查找 “bug”（不在词表中），再查找 “bu”（不在），最后查 “b” 和 “ug”（都在），于是切分为 ['b', 'ug']。

2.5 本章小结

本章我们掌握了驱动 Agent “大脑”所需的核心 LLM 知识：

  • 语言模型从 N-gram 统计方法演进到基于 Transformer 的现代架构
  • 自注意力机制是 Transformer 的核心——让每个词能”看见”上下文中的所有其他词
  • 采样参数（Temperature、Top-k、Top-p）控制模型输出的随机性和确定性
  • 提示工程提供了与 LLM 交互的基本技巧，但 Agent 的 Prompt 更像一份通信协议
  • 分词（尤其是 BPE）是将文本转换为模型可处理形式的关键步骤
