9  评估与持续改进

Note上一章回顾

第 9 章我们构建了多智能体协作系统。现在你的工具箱里已经有了从单 Agent 工具调用到多 Agent 协作的完整能力。但还有一个关键问题没有解决：如何客观地评估你的 Agent 做得好不好？如何系统性地改进它？ 这是工程落地的最后一公里。

9.1 评估基础

9.1.1 为什么要评估

在 Agent 开发中，评估不是可选项——它是验证能力、发现问题、做出数据驱动决策的基石：

  • 验证能力：Agent 是否真的具备预期的功能？
  • 发现问题：Agent 在哪些任务上表现薄弱？
  • 对比决策：两个不同配置的 Agent，哪个更好？
  • 防止回退：修改代码后，性能是否下降了？

9.1.2 评估的核心要素

要素 说明 示例
评估指标 衡量性能的标准 准确率、响应时间、Token 消耗
评估任务 Agent 需要完成的具体任务 “翻译下面的英文”
评估数据集 一组相关的评估任务 50 条中英翻译对
评估器 执行评估过程的组件 自动对比输出与期望

9.2 评估指标

9.2.1 准确率指标

def compute_accuracy(output: str, expected: str, match_type: str = "contains") -> float:
    """计算输出与期望的匹配度"""
    if match_type == "exact":
        return 1.0 if output.strip() == expected.strip() else 0.0
    elif match_type == "contains":
        return 1.0 if expected in output else 0.0
    else:
        raise ValueError(f"Unknown match_type: {match_type}")

# 示例
print(compute_accuracy("The capital of France is Paris.", "Paris", "contains"))  # 1.0
print(compute_accuracy("4", "4", "exact"))  # 1.0

9.2.2 响应时间与 Token 消耗

在实际部署中，响应时间和成本同样重要：

import time


def evaluate_with_metrics(agent, task: str, expected: str) -> dict:
    """运行一次评估，收集多维指标"""
    start = time.time()
    output = agent.run(task)
    elapsed = time.time() - start

    return {
        "accuracy": compute_accuracy(output, expected),
        "response_time": round(elapsed, 2),
        "output_length": len(output),
    }

        "category": "explanation",
        "difficulty": "medium",
    },
]


def run_benchmark(agent, benchmark: list[dict]) -> dict:
    """运行完整的 Benchmark"""
    results = []
    for item in benchmark:
        output = agent.run(item["task"])
        score = compute_accuracy(output, item["expected"]) if item["expected"] else None
        results.append({
            "task": item["task"][:40],
            "category": item["category"],
            "accuracy": score,
        })
    return results

9.3 基于强化学习的智能体训练

评估发现问题后，下一步是系统性地改进。除了手动调整 Prompt 和工具，强化学习（RL）提供了自动优化的途径。

9.3.1 为什么需要 RL

传统的 Agent 改进依赖人工规则和 Prompt 调整，但这种方式的局限性很明显：

  • 复杂任务中，人工无法枚举所有规则
  • 规则之间可能互相冲突
  • 每次场景变化都需要重新手工调整

RL 的思路是：让 Agent 在与环境的交互中自动学习最优策略。

9.3.2 强化学习核心概念

┌──────────┐   Action (a)   ┌───────────┐
│  Agent   │ ──────────────→ │Environment│
│  (LLM)   │ ←────────────── │           │
└──────────┘  State(s),      └───────────┘
              Reward(r)
概念 Agent 领域中的含义
状态（State） 当前对话历史 + 工具调用结果
动作（Action） LLM 生成的下一步文本/工具调用
奖励（Reward） 对 Agent 行为好坏的量化反馈

9.3.3 奖励函数设计

奖励函数是 RL 训练的核心——它告诉 Agent 什么是”好”的行为：

class AgentReward:
    """Agent 奖励函数示例"""

    def compute(
        self,
        task_completed: bool,
        steps_taken: int,
        user_satisfaction: float | None = None,
    ) -> float:
        reward = 0.0

        # 完成任务给予正向奖励
        if task_completed:
            reward += 1.0
        else:
            reward -= 0.5  # 未完成惩罚

        # 步数越少越好（鼓励高效）
        reward -= steps_taken * 0.05

        # 用户满意度（如果可获取）
        if user_satisfaction is not None:
            reward += user_satisfaction * 0.5

        return reward


# 示例
reward_fn = AgentReward()
print(reward_fn.compute(task_completed=True, steps_taken=3))          # 0.85
print(reward_fn.compute(task_completed=False, steps_taken=8))         # -0.90

9.3.4 GRPO：面向 LLM Agent 的训练方法

群组相对策略优化（GRPO） 是近年兴起的一种适合 LLM Agent 的训练方法。其核心思路是：

  1. 对同一个任务，让 Agent 生成多个不同的响应（群体采样）
  2. 用奖励函数对每个响应打分
  3. 将高分的响应作为”正样本”、低分的作为”负样本”
  4. 用对比学习的方式更新模型参数

与传统 RL 的区别在于：GRPO 不依赖绝对奖励值的精确性，而是通过相对比较来学习——这对于难以精确定义”最优行为”的 Agent 任务尤为重要。

9.4 评估与改进的工程实践

9.4.1 建立评估 Pipeline

代码修改 → 运行 Benchmark → 对比历史基线 → 决策
    ↑                                          │
    └────────── 如果性能下降，回退 ──────────────┘

9.4.2 持续改进清单

  1. 建立 Baseline：每个 Agent 版本都应有一条基准评估记录
  2. 小步迭代：每次只改一个变量（Prompt、工具、模型参数），能准确归因
  3. 自动化评估：将 Benchmark 集成到 CI/CD 中，每次提交自动运行
  4. 保留 Bad Cases：收集 Agent 出错的案例作为回归测试集
  5. 关注综合指标：不要只看准确率——响应时间、Token 消耗、用户满意度同样重要

9.5 本章小结

本章为 Agent 开发补上了关键的”闭环”：

  • 评估指标：准确率、响应时间、Token 消耗等多维衡量
